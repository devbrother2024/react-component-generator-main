# Git 커밋

1. `git status --short`, `git diff`, `git diff --cached`로 작업 트리와 스테이징 영역을 확인한다. 추적되지 않은 파일은 요청 범위에 해당할 때 내용을 확인한다.
2. 변경사항을 목적별로 묶는다. 한 파일에 여러 목적의 변경이 섞여 있으면 필요한 부분만 스테이징할 수 있도록 커밋 범위를 정한다.
3. 각 묶음에 `<유형>: <한국어 요약>` 형식의 메시지를 작성한다. 기능 추가는 `feat`, 버그 수정은 `fix`, 동작을 유지하는 구조 개선은 `refactor`, 유지보수 작업은 `chore`를 사용한다.
4. 커밋 요청을 받으면 별도 승인 없이 진행한다. 각 묶음에 해당하는 변경만 스테이징하고 `git diff --cached`로 범위를 확인한 다음 커밋한다. 커밋 해시와 메시지를 알려준다.
